## Anomalies et plan de correction

1. **Coût surestimé et modèles datés mal tarifés.** Les tokens en cache sont
   comptés au plein tarif ; un nom de modèle inconnu retombe silencieusement
   sur nano. Le run annonce 0,02166275 USD. Avec les tarifs standard de mini
   (0,25 USD/M entrée, 0,025 USD/M entrée en cache, 2 USD/M sortie), le calcul
   donne **0,01391555 USD**, soit 0,00774720 USD de moins. Corriger le calcul,
   reconnaître les snapshots datés des modèles connus et refuser un tarif
   inconnu avant transport. Il s'agit d'une estimation, pas d'une facture.
   [Tarifs officiels](https://developers.openai.com/api/docs/pricing),
   [GPT-5 mini](https://developers.openai.com/api/docs/models/gpt-5-mini).
2. **Proposition de menace non factuelle acceptée.** Pour Printemps,
   `ITM-56fe2e286f88ef44`, la proposition `Phishing / fraude` cite :
   « Ces informations peuvent notamment être utilisées pour construire des
   tentatives de phishing ou de smishing personnalisées. » Le validateur accepte
   ce risque futur. La menace principale publiée reste `Fuite de données` grâce
   aux autres règles et corrections ; cela ne rend pas l'extraction correcte.
   Ajouter une garde ciblée et revalider ce champ dans les caches historiques.
3. **Cache lié au modèle demandé au lieu du modèle routé.** SourceFacts emploie
   nano dans sa clé alors que le transport exécute mini. L'extracteur atomique
   présente le même défaut et écrit aussi le modèle demandé dans son résultat.
   L'override de tâche peut donc relire des valeurs d'un autre modèle. Lier les
   caches au modèle résolu ; préserver les anciens caches uniquement quand leur
   provenance établit la compatibilité.
4. **Réponse interrompue ou incomplète assimilable à un résultat.** Les parseurs
   cherchent un texte JSON sans vérifier systématiquement le statut de la réponse.
   SourceFacts traite aussi une clé absente comme une absence de fait. Refuser
   interruption, refus et champs requis absents avant d'écrire un cache ; compter
   les tokens facturables même si la validation échoue. L'API documente ces cas
   [dans Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
5. **Deux passes SourceFacts subsistent après l'élagage.** Les types de données
   peuvent encore déclencher une seconde soumission du même article. Réunir les
   champs nécessaires dans une seule demande, en conservant les restrictions
   de reprise et les abstentions en cache. Mesurer la réduction d'appels avec
   un transport simulé ; ne pas annoncer de gain de latence réel sans collecte.

## Qualité et décisions : ce qui est établi, ce qui reste limité

Les sorties structurées sont contrôlées : preuve présente dans l'article,
confiance bornée, taxonomie, activité de la victime distincte de celle d'un tiers,
réserves de menace et contraintes temporelles de fusion. Les 3 incidents publiés
sont Citadium, Printemps et Le Tampon. Les deux premiers restent des fuites de
données ; Le Tampon conserve une menace inconnue. Les secteurs du commerce
proviennent d'une référence, celui du Tampon d'une règle institutionnelle : zéro
couple activité/secteur demandé ne signifie pas que le LLM a validé ces secteurs.

Les 14 succès HTTP ne mesurent ni la fidélité sémantique ni la précision du
modèle. Une citation présente ne prouve pas à elle seule toutes les affirmations
d'un résumé. Certains champs historiques acceptés sont discutables : `Shipup`
comme lieu fin et des catégories de données comme jeux de données. Ils font
partie du contrat déjà retiré, sans motif pour les réintroduire.

Les résumés publiés de Citadium et Printemps comportent aussi des corrections
éditoriales. Leur qualité ne peut pas être attribuée exclusivement au LLM.
Le registre d'identité préexistant contribue au regroupement du Tampon ; ce run
ne démontre aucune nouvelle décision du filet de déduplication.

## Limites maintenues

- Le plafond de 0,03 USD est un seuil de coupure sur le coût déjà observé,
  pas une garantie comptable stricte : le dernier appel peut le dépasser.
- Le compteur d'appels partagé porte les demandes logiques ; les nouvelles
  tentatives HTTP sont suivies séparément. Les retries sont désactivés par défaut.
- L'extraction atomique et SourceFacts se recouvrent partiellement. Leur fusion
  complète demanderait de vérifier les consommateurs déterministes des faits ;
  supprimer cette étape sur le seul critère d'affichage risquerait de perdre
  des preuves de qualification. Le présent correctif conserve cette étape.
- Un seul run ne permet pas de comparer nano et mini ni de calibrer les scores
  de confiance. Pas de changement de modèle ni de budget sans mesure comparative.

## Corrections réalisées

- le prix de l'entrée en cache est compté séparément et les snapshots datés
  héritent du tarif de leur famille ; un modèle sans tarif connu bloque avant
  l'appel ;
- une réponse interrompue, refusée ou privée d'un champ obligatoire reste
  comptabilisée, mais n'est ni mise en cache ni transformée en abstention ;
- les caches SourceFacts et atomiques sont liés au modèle résolu et conservent
  les identités demandée, résolue et déclarée ; la matérialisation sélectionne
  aussi le bon modèle ;
- le validateur rejette le phishing ou le smishing évoqué uniquement comme
  risque ou usage futur, et revalide les anciennes valeurs de menace ;
- les six champs du contrat SourceFacts courant partent dans une seule demande
  au maximum par article. Sur le run audité, la passe supprimée représentait
  6 appels, 16 039 tokens d'entrée dont 15 360 en cache, 1 232 tokens de sortie
  et 0,00301775 USD au tarif corrigé. Ce chiffre décrit l'ancien run ; le gain
  réel dépendra des champs manquants et des caches au prochain run ;
- la télémétrie expose les issues par champ, le taux d'acceptation et le coût
  par champ accepté.

Validation locale initiale : 1 261 tests passent, Ruff ne remonte aucune erreur
et les contrôles statiques ciblés passent. À ce stade, aucun appel API réel ni
nouvelle collecte n'avait été lancé.
